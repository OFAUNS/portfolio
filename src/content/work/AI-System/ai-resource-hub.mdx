# AIevent 活動情報整合 App

>想知道「最近有什麼值得去的活動」，得開十幾個網站各自翻一遍，
翻完還是不確定有沒有漏掉。這個 App 處理的是來源分散造成的資訊成本，
不是再多做一個活動列表。

---

![趨勢首頁：來源、紀錄、可行動與警示的即時計數](/work/ai-resource-hub/hub-01.png)

## 頂欄的四個數字就是整個系統的狀態

**SOURCES / RECORDS / ACTIONABLE / ALERTS**——來源數、匯流進來的總筆數、
還沒過期可以去的場次、以及需要注意的提醒。左側把資料切成技術活動、
日常活動、還沒歸類、歷史資料庫，**「還沒歸類」是刻意留著的**：
分類器判不出來的就放進去，不硬塞到某一類假裝分完了。

## 趨勢分成三種，每一則都要說「對你的意義」

突破、轉向、用法——分別對應「技術天花板動了」「遊戲規則變了，舊決定該重算」
「現在該怎麼用才對」。每一則趨勢底下固定有一段「對你：」，把新聞翻譯成
對手上專案的具體影響，並列出資料庫裡相關的場次。

沒有這一段的話，趨勢頁就只是另一個 RSS。

## 「來源完全沒涵蓋」也是一種情報

右側的 **GAP 來源缺口** 面板列的是——這幾個主題在目前的來源裡完全查不到。

缺口本身就是情報：它告訴你該補哪一顆來源，比多列幾則新聞有用。
同樣的邏輯用在關注場地清單上，31 個指定展場裡有 18 個一筆資料都沒有，
系統把這 18 個列出來而不是藏起來，下一步該補什麼來源就直接被指出來了。

## 不做排行榜，做對照表

「模型與工具」那一頁刻意不排名。同一個項目在不同來源講法衝突時兩邊都列，
已經退場的也留著並標記——因為「這個東西已經不能用了」跟「這個東西很好用」
是同等重要的資訊。

## 系統狀態放在最顯眼的地方

左下角常駐三行：匯流是否待命、API 憑證有沒有設定、資料完整度。
畫面上方那條黃色橫幅寫的是「後端還沒拿到 API 金鑰，AI 抽取會失敗；
匯流與 regex 解析不受影響」——**壞掉的時候要明確說哪一部分壞了、
哪一部分還能用**，而不是整頁靜悄悄地少一半資料。
